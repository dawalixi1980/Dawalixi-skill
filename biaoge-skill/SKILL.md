# biaoge-skill — Word 表格后处理器

## 定位

**生成后的收尾技能**。它不生成内容，只处理已成型的 `.docx`：把 pandoc（或任何工具）产出的表格，调成"列宽贴合内容、风格全册统一、适配分栏"的交付状态。

```
pandoc / Word / 其他工具  →  *.docx  →  [本技能]  →  可交付的 *.docx
```

## 为什么必须放在"生成 Word 之后"

| 时机 | 能控制什么 | 控制不了什么 |
|---|---|---|
| pandoc 转换时（`--reference-doc`） | 字体、边框、行高 | ❌ 列宽（pandoc 按参考文档的固定默认宽度均分）❌ 分栏 ❌ 按内容算宽 |
| **生成后（本技能）** | ✅ 逐格量文字、按内容算列宽 ✅ 读 `w:cols` 适配分栏 ✅ 全册统一样式 ✅ 清模板页眉页脚 | — |

**结论：先转换，再用本技能收尾。**

## 触发时机

- 用户提到：表格优化、表格样式、列宽、表格太窄/超宽、超出栏框、表格折行、分栏文档表格、统一表格风格
- 完成 `.docx` 生成后（pandoc / Word COM / python-docx 导出），作为交付前最后一道工序
- 发现"表格横跨两栏""表格只占半页宽""两三个字就换行""整册表格风格花"等症状时

## 执行协议（强制）

### 第 0 步：先诊断，不要直接改

```bash
python "<skill_dir>/scripts/inspect_docx.py" "<输入.docx>"
```

输出包含：
- **分节与分栏**：页面尺寸、版心、栏数、**单栏可用宽度**（表格宽度的真正上限）
- **页眉/页脚检查**：是否有文字或图片残留（⚠ 模板图签常带**其他项目名**，暗标致命）
- **表格概况**：张数、列数分布
- **逐表列宽与内容余量**：当前总宽 vs 可用栏宽，判定"偏窄/超宽/合适"

把诊断结果**先说给用户听**（尤其分栏数与页眉页脚告警），再进入下一步。

### 第 1 步：让用户选样式（必须交互）

用选项形式让用户挑，**一个 Word 只用一种样式**。列出 6 个预设：

| 预设 key | 名称 | 适用 |
|---|---|---|
| `three-line` | 三线表 | 正式文件、学术、规范体；最简洁 |
| `grid-plain` | 全网格无底色 | 全网格线、零底纹、仅表头加粗；最朴素干净 |
| `grid` | 标准网格 | 全网格 + 浅灰表头，通用性最强 |
| `zebra` | 斑马隔行 | 行多、需要横向追踪 |
| `dark-header` | 深色表头 | 需要强层次、封面级表格 |
| `label-col` | 标签列强调 | "标签—内容"型（首列是类别） |
| `head-rule` | 表头下线 | 最轻量，只有表头上下两条线 |

可用 `--list-styles` 打印说明。**未获用户选择前不要擅自决定。**

### 第 2 步：执行

```bash
python "<skill_dir>/scripts/fit_tables.py" "<输入.docx>" \
  -o "<输出.docx>" \
  --style three-line \
  --font-size 10.5 \
  --caption \
  --clean-header
```

参数：

| 参数 | 说明 | 默认 |
|---|---|---|
| `--style` | 6 个预设之一，必填 | 无（必须指定） |
| `--font-size` | 表体字号（pt） | 10.5（五号） |
| `--header-rows` | 表头行数 | 1 |
| `--min-chars` | 每列最小宽度（中文字数） | 4 |
| `--no-fill` | 不撑满栏宽，仅用内容最小宽 | 关（默认撑满） |
| `--caption` | 加"表 N  标题"题注 | 关 |
| `--clean-header` | 清空页眉页脚（去模板图签残留） | 关 |
| `--strip-hr` | 删除 pandoc 由 `---` 生成的 VML 水平线 | 关 |
| `--dry-run` | 只测算不写文件 | 关 |

### 第 3 步：验证

1. 用 Word 打开输出文件（或 Word COM 转 PDF），确认页数与表格数
2. 抽查 2～3 张表：**能否单行放下的都放下了**、**表格不越栏**
3. 报告"仍会折行的列数"（脚本已输出），并说明哪些列因为内容本就很长而折行

## 核心算法

### 1. 分栏自适应

表格宽度上限**不是版心宽，而是单栏宽**：

```
单栏宽 = (页宽 − 左边距 − 右边距 − 栏间距 × (栏数 − 1)) / 栏数
```

脚本读 `w:sectPr/w:pgSz`、`w:pgMar`、`w:cols`；若 `w:cols` 里给了显式 `w:col w:w`，直接用该值。多节文档按节分别计算。

> ⚠ 常见坑：A3 横向 + 双栏时，版心 350mm 但**单栏只有 162.6mm**。按版心设表宽会让表格横跨两栏。

### 2. 动态列宽（注水法）

1. **逐格量宽**：按单元格文字累加字宽——中日韩字符算 1 em，数字 0.55 em，大写 0.65 em，小写 0.52 em，空格 0.28 em，其他 0.5 em；再乘以字号换算成 twips，加上单元格左右边距
2. **取每列最宽格**作为该列"单行所需宽度" `d_i`
3. **Σd ≤ 可用宽** → 全部单行，剩余宽度按比例分配，表撑满栏宽
4. **Σd > 可用宽** → 二分求上限 `W`，每列取 `min(d_i, W)`，使总和恰为可用宽

效果：**短列保持单行，只有真正最长的列才折行，且折行量在各列间公平分摊**；再叠加 `--min-chars` 保底，避免某列被压成一字一行。

### 3. 清零单元格段落缩进（**最容易漏的一步**）

中文 Word 模板常用**字符级**缩进 `w:ind w:firstLineChars="200"`（首行缩进 2 字符）。单元格段落会继承它，等于每行白吃 2 个字宽，使本可单行的文字折行。

只设 `w:firstLine="0"` **无效**——Word 里 `firstLineChars` 优先级更高。必须同时清零：
`firstLineChars` / `leftChars` / `rightChars` / `hangingChars`。

脚本在 `format_cell_paragraphs()` 中一并处理，并把段前段后间距与行距归一。

### 4. 样式统一

`apply_style()` 对**每一张表**施加同一预设：边框（6 条边可分别设 无/线宽/灰度）、表头底纹与字色、斑马底纹、标签列底纹、单元格垂直居中、跨页重复标题行、表体字号。

### 5. 清理 pandoc 残留（`--clean-header` / `--strip-hr`）

pandoc 产出的 docx 常带两类与内容无关的残留，都在暗标场景有风险：

| 残留 | 形态 | 风险 | 开关 |
|---|---|---|---|
| 模板页眉图签 | 页眉里的**图片**（`word/media/imageN.jpeg`） | 可能带**其他项目名称/图号**，暗标致命 | `--clean-header` |
| Markdown `---` 水平线 | `<w:p><w:r><w:pict><v:rect o:hr="t"/></w:pict></w:r></w:p>` | 章节间多出横线，非文档内容 | `--strip-hr` |

`--strip-hr` 的难点在于：这条线**既不是段落边框（`w:pBdr`）也不是表格边框**，而是 **VML 图形**（`v:rect` + `o:hr="t"`）。常规的 pBdr 清理手段查不到，必须按 VML 元素识别。

## 灰度色板（全部黑白灰）

`000000` 黑 ｜ `595959` 深灰 ｜ `808080` 中灰 ｜ `BFBFBF` 浅灰 ｜ `D9D9D9` 更浅
底纹：表头 `F2F2F2`、深表头 `404040`、斑马 `F7F7F7`、标签列 `EDEDED`

线宽（八分之一磅）：`4` = 0.5pt，`8` = 1pt，`12` = 1.5pt，`18` = 2.25pt

## 反模式

1. ❌ 不看 `w:cols` 就按版心设表宽 → 表格横跨两栏
2. ❌ 一个 Word 里混用多种表格样式 → 应让用户选一种，全册统一
3. ❌ 只清 `w:firstLine` 不清 `w:firstLineChars` → 缩进仍在，文字照折行
4. ❌ 列宽一律均分 → 短列浪费、长列折行
5. ❌ 直接改原文件 → 应输出到新文件，保留原件
6. ❌ 忽略页眉页脚里的模板图签 → 可能带出**其他项目名称**，暗标致命
7. ❌ 未让用户选样式就动手
