# 匹配度评分 与 5 选表格写法

脚本给出的 `coverage` / `coverage_original` / `exact_name` 只是**机械预排序**,档位判定是 LLM 的活。档位固定四档,禁止使用"比较像""应该就是"这类模糊说法,也不许算"总分"。

> `coverage` / `exact_name` 以**生效查询**为基准(降级后按降级那一轮算),`coverage_original` 才是拿用户原始输入算的——所以降级后 `coverage` 可以是 1.0 而 `coverage_original` 只有 0.5,这不是矛盾,而是"我们丢了词但结果对得上"。

## 1. 四档定义

| 档位 | 判据(全部满足才算) | 典型 |
|---|---|---|
| **精确** | 归一化后 文件名 == 用户给的名称(`exact_name=true`),且类型/上下文不矛盾 | 用户说"AD-03 一般路基设计图",文件名就是它 |
| **高** | 用户核心词**全覆盖**(去停用词后每个词都在文件名里),但名称有增减(编号、后缀、`- 副本`) | `AD-03 一般路基设计图 (1).dwg` |
| **中** | 缺 1 个词,或命中 ≥60% 的词,或词序/写法不同(简繁、全半角、空格差异) | 用户说"路基横断面支护大样",文件名是"路基横断面设计图" |
| **低** | 只命中 1 个词,或仅靠通配/正则擦边命中 | 用户说"防护大样",命中的是"路基防护设计图" |

归一化规则(与脚本一致):去扩展名 → 去空白与 `空格 - _ （）() 【】[] ,，.。、` → 英文转小写。

## 2. 并列时的定序规则(依次比较,前者决定则不进入下一条)

1. **命中词数**:命中的用户词更多者优先。
2. **目录语义**:文件名同等时,路径里出现用户语境词的优先(用户说"投标",路径含 `TB-投标` 者优先);工作目录/用户当前项目目录下的优先。
3. **修改时间**:更晚者优先(用户多半要的是最新版)。
4. **扩展名与上下文一致**:用户说"图纸/设计图"→ `.dwg` 优先于 `.pdf`/`.jpg` 扫描件;用户说"表格/清单"→ `.xlsx` 优先。

四条比完仍并列 → 报 `AMBIGUOUS`,在结论里写明"无法唯一确定",让用户挑。

## 3. 匹配理由怎么写

每条理由必须包含**至少一项可验证证据**:命中了哪几个词 / 命中了哪个目录语义词 / 时间或大小为何符合。禁止"看起来相关""应该就是它"。

| 差 | 好 |
|---|---|
| 名字很像 | 命中"路基""防护""设计图"三个词,与查询全部重合;`ext:dwg` 与"图纸"语境一致 |
| 这个是新的 | 2024-07 修改,是候选里最新的一份;路径 `07-路基防护` 与查询的"路基防护"语义吻合 |
| 就是这个 | 归一化后与查询完全一致(精确档);位于当前工作目录下,是同名文件中的唯一 .dwg |

## 4. 实例(本机真实命中)

查询:`AD-03 一般路基设计图`,无结果时 R2 用 `AD-03 一般路基设计图` 直查,按 `path:`/`ext:` 收窄后实际候选:

| 候选 | 判定 | 依据 |
|---|---|---|
| `H:\projects\demo\cad 图纸\AD-03 一般路基设计图.dwg` | **精确** | 文件名与查询完全一致;正处于当前工作目录;dwg 与"设计图"一致 |
| `H:\projects\bid\…\专业 3\A 道路工程\AD-03 一般路基设计图.dwg` | 高 | 文件名一致,但路径属于另一个项目(投标),时间/项目不符 |
| `C:\Users\…\Documents\PDF files\自动保存\AD-03 一般路基设计图 副本1 (1).pdf` | 中 | 命中 `AD-03`、`一般路基设计图`;但是 PDF 副本,非原生图纸 |

→ 结论写法:`我判断最匹配的是 #1`(精确档 + 位于当前工作目录)。

## 5. 数量规则

- 候选 ≥5:给 5 条,其余用一句话概括(如"另 3 条同名文件在 Z: 盘 2018 年前的项目目录里")。
- 候选 1–4:全列,表格下方注明"索引中共 N 条,已全部列出"。
- 候选 0:不出空表,报 `NO_MATCH`,给 2 条改词建议。
- 命中 > 200:先给总数与收窄建议,再列 5 条,并注明"这是收窄前结果"。
