# everything-find

用本机 **Everything** 索引按名称找文件。搜索是机械的,判断最匹配 **是 LLM 的活**:脚本只给候选和机械得分,由你按评分档位挑出 5 条、写明理由、指出最匹配的那一条。

## Invariants(不可协商)

1. **路径必须是完整绝对路径**,直接来自索引结果,不得拼接、缩写、省略盘符,不得把"目录 + 文件名"当路径交付。
2. **不许编造结果**。索引里没有就是没有,报 `NO_MATCH`;不许把"大概应该在这个目录"写成候选。
3. **候选不足 5 条就写实际条数**,不补齐、不凑数;候选为 0 时不输出空表格。
4. **评分只影响排序**,不影响如实报告。你的第一名也要允许用户否掉,不许把判断说成事实。
5. **只读**。打开、复制、移动、改名、删除文件都必须另获用户明确许可(改图纸归 CAD 侧工具)。
6. **只用本次脚本返回的候选**。不许从对话历史里翻旧结果充数;索引是实时的,旧结果可能已经不存在。
7. **命中很多不等于找到了**。总数 > 200 时先收窄(加类型/目录/时间),不要在一堆同名文件里硬选。

## 状态机

一次请求只走一条路径,每步都有可检查的产物:

```
intake -> query_build -> search -> verdict -> (ladder) -> rank -> present
```

| 状态 | 产物 | 判定 |
|---|---|---|
| `intake` | 名称/关键词 + 可选约束(类型、位置、时间) | 只有"帮我找个东西"这种无词请求 → 问一句再走 |
| `query_build` | 一条 Everything 查询串 | 见"查询构造" |
| `search` | `results.json`(候选 + 轮次 + 命中数) | 脚本退出码 0 且 `error_code != TOOL_UNAVAILABLE` |
| `verdict` | 命中数分档结论 | 0 → 进阶梯;1–5 → 全列;>5 → 选 5;>200 → 先收窄 |
| `ladder` | 每轮"查询串 + 命中数"留痕 | 首次命中即停,最多 4 轮 |
| `rank` | 5 条带档位与理由的候选 | 见 references/ranking-rubric.md |
| `present` | 固定列 markdown 表 + 最匹配结论 | 见"输出契约" |

## 输入契约

必需:**一个名称或关键词**。缺 → 问一个 blocking question,不要瞎搜。

可选(有就用,没有别问):文件类型(`dwg`/`pdf`/`xlsx`…)、范围(某个盘或目录)、时间、大小。

## 查询构造

- 空格 = **AND**,`|` = OR,`!` = NOT,`*` `?` = 通配;`ext:dwg;pdf`、`path:`、`parent:`、`size:`、`dm:2024`、`rc:` 可用。
- 名称不确定时**先不加** `ext:`,加类型会漏掉用户没说的正确结果。
- 中文名不要拆字;名里含 `& | > < ^` 必须引号包住或 `^` 转义。
- **每个词必须作为独立参数传给 es.exe**:含空格的单个参数会被当成整词,多词查询几乎全部 0 命中(实测 `'AD-03' '设计图'` → 7 条,`'AD-03 设计图'` → 0 条)。脚本已内置该规则,自己手写命令时必须照做。
- `path:` 过滤器在本机 Everything **1.4 不生效**(实测恒为 0);限目录请用脚本的 `-Path`(内部走 es 的 `-path`)。
- `-Path` 传短路径(8.3 形式,如 `C:\Users\ADMINI~1\...`)**会恒 0 命中**——Everything 的 `-path` 只认长路径。脚本已自动用 `Get-Item` 规范化,JSON 里 `path_filter` 是实际使用的长路径、`path_filter_input` 是你传进去的原值。
- 细节与实测坑见 [references/everything-syntax.md](references/everything-syntax.md)。

## 搜索命令

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<skill>\scripts\ev-search.ps1" `
  -Query "<用户给的名称或关键词>" -Ladder
```

常用参数:`-Ext dwg` / `-Path "H:\某目录"` / `-Regex` / `-Count 50` / `-Transport auto|es|http`。

脚本行为:**只往控制台打一行纯 ASCII 摘要**,完整候选写到 JSON 文件:

```
SCHEMA=everything-find/result/v1 TRANSPORT=es USED_ROUND=0 HITS=12 RETURNED=12 TRUNCATED=0 JSON=<路径> ERROR=NONE ESC=1.1.0.27 EV=1.4.1.1032
```

拿到 `JSON=` 路径后**必须用 read 工具读该文件**,再据 `results` 做排序与出表。字段含义:

| 字段 | 含义 |
|---|---|
| `results[].path` | **完整绝对路径**(交付必须用它) |
| `results[].name` / `dir` / `ext` | 文件名 / 所在目录 / 扩展名 |
| `results[].size_bytes` / `size_human` / `modified` | 大小与修改时间 |
| `results[].coverage` | 生效查询词在文件名里的覆盖率(0–1;降级后按降级查询算) |
| `results[].coverage_original` | 相对**用户原始输入**的覆盖率(降级后必然偏低,用于说明丢了多少词) |
| `results[].exact_name` | 名称归一化后与**生效查询**是否完全一致 |
| `effective_query` | 实际生效的查询串(降级后就是采用那一轮) |
| `name_query` | 只保留名称词的查询(已剔除 `ext:`/`size:`/`dm:`/`path:` 等函数过滤器);`coverage` 与 `exact_name` 以它为准,否则一加 `-Ext` 就永远不准 |
| `rounds[]` / `used_round` | 每轮查询串、词条与命中数 / 最终采用第几轮 |
| `total_hits` | 该轮的索引命中总数(可能远大于返回条数) |
| `truncated` | 是否因 `-Count` 截断 |

## 判定与收窄

| 命中数 | 动作 |
|---|---|
| 0 | **不许直接说"没有"**,进阶梯 |
| 1–5 | 全部列出 |
| 6–200 | 按评分挑 5 条 |
| > 200 | 先报总数,给出 2–3 条收窄建议(加 `ext:`/`path:`/`dm:`),再列 5 条并说明"这是收窄前的结果" |

**名称词一个都命中不到时,不要只靠删词**:异体字和语序错误,删词救不回来。此时用**目录枚举**兜底——
先猜可疑目录(从同级目录名、项目树、已知同类文件的落点推),再用 `-Path "<目录>"` + 一个万能词(如 `ext:pdf`)
把该目录列出来,逐个比对文件名。实测案例:用户写「**安**马屯」「崆**垌**」,文件名是「**马**安屯」「崆**峒**」,
按名字搜恒 0,枚举目录一次命中。

## 删词阶梯(最多 4 轮,每轮留痕)

原始查询 0 命中时**自己降级**,不要回来问用户"你要找的是不是别的名字":

| 轮 | 动作 | 例子 |
|---|---|---|
| R1 | 去扩展名、去 `- 副本`/`(1)`/`_v2` 等尾缀 | `支护大样图.dwg` → `支护大样图` |
| R2 | 去括号内容与流水编号 | `03 路基防护（含边坡）` → `路基防护` |
| R3 | 拆词,留最长的 **2 个**特征词(AND) | `AD-03 一般路基设计图` → `AD-03 一般路基设计图` |
| R4 | 只留最长的 **1 个**特征词 | `一般路基设计图` |
| R4b | 仍 0 且该词长度 ≥4 时加前缀通配 | `一般路基设计图*` |

规则:首次命中即停;每轮记录"轮次 / 查询串 / 命中数";交付时要说明**用了第几轮、降了什么词**。完整定义见 [references/fallback-ladder.md](references/fallback-ladder.md)。

## 评分与选 5

四档固定档位:**精确 / 高 / 中 / 低**,并列时按 4 条规则依次定序(命中词数 → 目录语义 → 修改时间 → 扩展名与上下文一致)。

理由必须写**具体证据**(命中了哪几个词、目录语义为什么对、时间为什么新),不许写"看起来相关"。完整评分表与写法示例见 [references/ranking-rubric.md](references/ranking-rubric.md)。

## 出图判读

候选里有 `dwg`、或用户问"这张图到底对不对"时,**先出图再判读**——文件名会骗人,图不会:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<skill>\scripts\dwg-shot.ps1" `
  -Path "<dwg 路径>" -Text -Width 2400
```

- 走**无头 AutoCAD**(`accoreconsole`):矢量 PDF → 光栅化 PNG,**不需要人开 CAD**、不弹窗、不碰用户正开着的图纸;单张实测约 **11 秒**
- 默认 `-Mode auto`:先按**布局**出图(真实交付图的 A3 图框/标题栏/图名图号都在布局里);若该页墨量 < 0.2%(空页)再回退**模型空间 + 自动窗口**(自动剔除游离图签)
- `-Text` 顺带抽全图文字到 `<tag>.text.txt`(**图名/图号/说明/表格**)——这是"图纸对不对"**最便宜、最可靠**的判据,优先用它,再考虑看图
- 控制台只打 ASCII 摘要;**真实路径、窗口、墨量在 `manifest.json`** → 必须用 read 工具读
- `-Width` 建议 **2000–2500**:视觉模型会自己降采样,更大只是浪费
- 出图后:用 read_image 看 PNG,把「图名 / 图号 / 关键构造」与用户意图核对,再进入"评分与选 5"

实测(AD-03 一般路基设计图):布局出图墨量 **2.12%**,图名「路基一般设计图」、图号「AD-03」、土基压实度表与四条说明全部清晰可读;同一张图改用模型空间"范围"出图墨量只有 0.74%(游离图签把主体缩没了)。

应答链、四个坑与局限见 [references/dwg-shot.md](references/dwg-shot.md)。**只读**:PDF/PNG/DXF 只写临时目录,绝不改原图。

## 输出契约(固定)

表格列**必须**是这 6 列,顺序不变:

| 序号 | 文件名 | 完整路径 | 大小 / 修改时间 | 匹配度 | 匹配理由 |
|---|---|---|---|---|---|
| 1 | AD-03 一般路基设计图.dwg | `H:\projects\demo\cad 图纸\AD-03 一般路基设计图.dwg` | 2.1 MB / 2024-07-03 | 精确 | 名称归一化后与查询完全一致,类型相符 |

表格之后**必须**补三行元信息,缺一不可:

1. **查询词**:本次实际使用的查询串(降级了就写阶梯链路,如 `"AD-03…副本(1)" → R2 "AD-03 一般路基设计图"`)
2. **命中总数**:该轮命中多少条(≠ 表格行数时要说明)
3. **最匹配结论**:`我判断最匹配的是 #N`,一句话理由;若两个候选同档且语义不同 → 明确写"无法唯一确定",让用户挑

## 错误码

| 码 | 含义 | 交付动作 |
|---|---|---|
| `NONE` | 正常 | 正常出表 |
| `NO_MATCH` | 4 轮阶梯后仍 0 命中 | 如实说没搜到,列出最后 1 轮用的词,给 2 条改词建议 |
| `AMBIGUOUS` | 多个候选同档且语义不同 | 出表并明确写"无法唯一确定" |
| `TOOL_UNAVAILABLE` | es.exe 与 HTTP 都不可用 | 报路径,给降级说明,**不许假装搜过** |
| `BAD_ARGS` | 参数不合法 | 修正参数重跑 |
| `QUERY_TIMEOUT` | 索引未加载完/超时 | 重试一次;仍失败按 `TOOL_UNAVAILABLE` 处理 |

## 宿主能力与降级

`es.exe`(IPC,首选)→ Everything HTTP 服务(次选)→ 都没有则 `TOOL_UNAVAILABLE`。三条路径的差异、损失与不许假装的事见 [references/host-capabilities.md](references/host-capabilities.md)。

## 不做的事

- 不修改任何文件:出图/抽文字只往临时目录写 PDF/PNG/DXF;
- 不打开、不移动、不改名、不删除;
- 不凭渲染图臆测文字:小字看不清时,以 `dxf-text.py` 抽出的文字为准;
- 不把"路径存在"当成"这份图纸是正确版本"的证明;版本对错要让用户确认;
- 不用 Everything 搜网络或云端盘(索引范围见 `-get-result-count` 边界,只覆盖本机已索引卷)。
