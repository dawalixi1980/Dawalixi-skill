# yf-skill — 来源隔离的项目归档同步

## 模型

- **NAS 项目**：固定 8 个顶层分类 `01招投标合同…08其他资料`（**不含**过程/成果子层）。
- **本地工作**：在同样 8 个分类里整理文件（如 `05初步设计\图纸1`）。
- **同步上云**：本地 `05初步设计\图纸1` → NAS `05初步设计\<本机主机名>\图纸1`。
- **互不覆盖**：本机只写 `分类/<主机名>/`，可覆盖自己旧的；**别的来源文件夹永不改动**。
- **未归类拒绝**：本地根目录出现 01-08 之外的东西 → 直接拒绝同步。

## 命令

| 命令 | 作用 |
|---|---|
| `yf run [路径]` | 检索 NAS 项目 + 把 01-08 架构补进本地当前文件夹（建立映射） |
| `yf go [路径]` | 同步到 NAS 的 `<主机名>` 层（未归类直接拒绝） |
| `yf pull [路径]` | 选【分类 + 来源(主机名)】，推荐**最后同步时间最新**的来源，拉到本地 |
| `yf find <关键词>` | 按关键词搜项目 → 在项目里搜文件名 → 选着拉取到本地（`--into 目标目录`） |
| `yf sources [路径]` | 列某项目各分类下的来源及最后同步时间 |
| `yf whoami` | 看本机来源名(主机名)、IP、会写进哪 |
| `yf open [路径]` | 资源管理器打开该项目 NAS 文件夹 |
| `yf list` / `yf root <路径>` / `yf setup` | 映射与配置 |

## 给 Agent 的执行规则

- 用户说"同步、归档、yf go" → 在**目标项目文件夹**运行 `yf go`（未归类会拒绝，需先提示整理）。
- 用户说"检索/建立项目、yf run" → `yf run`。
- 用户说"拉取、下载别人的、yf pull" → `yf pull`（交互选择分类与来源）。

## 关键约定（决策记录）

- 来源名 = **主机名**（`COMPUTERNAME`），换电脑自动识别，无需配置。
- 骨架 = **只要 8 个顶层**，不建"过程文件/成果文件"。
- 日志 = NAS 上 **每机一份** `_同步日志\<主机名>.log` + 本地 `项目日志.txt`；字段含 时间/主机名/IP。
- `yf pull` 下载来的来源文件夹会写一个 `.yfsource` 标记，`yf go` 不会把它再传回去。
- 覆盖策略：同机覆盖自己；跨机新建来源文件夹。
- `nas_root` 建议用 **UNC**（`\\NAS\共享\...`），别写盘符。

## 已知取舍

- 每台电脑各存一份 → NAS 体积会累加；旧的孤儿来源需手工清。
- 无历史回滚（这是"共享文件夹+来源命名空间"，不是 git）；需要分支/历史请用 git。
- 大文件走 SMB 较慢，但增量同步只传变化。

## 安装（任意电脑一次）

```bash
python "<skill>/scripts/install_yf.py"
```

装到 `%USERPROFILE%\.yf` 并进 PATH（放在最前，覆盖旧的 yf）。
