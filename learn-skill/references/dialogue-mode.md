# 对话式教学（Dialogue Mode）

> learn-skill 的**交付层**。结构（顶层整体 ＋ 贯穿地基）由 D v4 负责编译成 Wiki；
> 对话负责把 Wiki 里的知识**一轮一轮送进脑子**。
> **铁律：Wiki 是唯一事实源，对话不是第二真相。**

## 零、一句话定位

| | 地图（Wiki / 骨架） | 走路（对话） |
|---|---|---|
| 性质 | 静态、可查、可追溯 | 动态、逐单元、即时反馈 |
| 职责 | 知识**怎么组织**（顶层＋地基） | 知识**怎么进入脑子** |
| 关系 | 对话读完立刻**回写** Wiki | 对话不清空、不替代 Wiki |

**为什么爽**：即时反馈 ＋ 自定节奏 ＋ 一次只面对一个小问题。
**为什么需要安全网**：对话易跑题、易"感觉懂了其实没沉淀" → 用**每轮落库**兜底。

## 一、五拍循环（核心节奏）

每一轮对话 = **讲 → 问 → 答 → 判 → 沉淀**。

| 拍 | 谁 | 动作 | 产出 |
|---|---|---|---|
| ① 讲 | LLM | 用**地基语言**讲一个「一体知识点单元」：先机制（如何作用在地基上），再语义；符号出图 | 一段讲解 |
| ② 问 | LLM | 抛一个**机制型**或**穿针**问题（见 question-design.md） | 一个问题 |
| ③ 答 | 用户 | 用**自己的话**回答（不许只回"懂了"） | 一段回答 |
| ④ 判 | LLM | `✔ / △ / ✘` ＋ 一句话点评 ＋（错了才）最小纠正 | 判定 |
| ⑤ 沉淀 | LLM | 写回对应 Wiki 单元 / 问题索引 / 缺口账本 / 钉子表；追加 log | 落库 |

**三条铁律**
1. **一轮只讲一个单元**——绝不一口气灌多个知识点。
2. **每轮至少一问**——没有提问的轮次不算对话，退化成单向讲课。
3. **每轮要么落库，要么显式声明"本轮无需沉淀"**——杜绝只聊天不沉淀。

## 二、每轮输出模板

```markdown
【本轮目标】<要素> · Q<n>：<问题>

【讲】<机制：它如何作用在【地基<元素>】上> → <语义：在顶层"在说什么">
      <符号>：![<图注>](./img/<名>.png)

【问】<机制型 / 穿针问题>

─────────（等用户作答）─────────

【判】<✔ 命中 / △ 半对 / ✘ 未中>　<一句话点评>
【沉淀】已写入 <wiki 路径> ；问题索引 Q<n> → [x]
【下一轮】<预告下一个单元 / 问用户是否继续>
```

## 三、四种对话模式

| 模式 | 用途 | 对位 D v4 阶段 | 起点 |
|---|---|---|---|
| **立骨架对话** | 边聊边敲定核心问题 / 领域公式 / 地基元素 | 第 0 ＋ 0.5 遍 | 空库，或已有不完整骨架 |
| **微课对话** | 学**单个**单元（最快、最爽） | 第 1 遍 | 指定某问题编号 |
| **串讲对话** | 走完**一个要素**的全部单元 | 第 1 遍（成组） | 某个要素页 |
| **复盘对话** | 抽问、关书复述、补缺口 | 第 2 遍 ＋ 1/3/7/30 复习 | `01-问题索引.md` |

> 起手建议：先确认骨架已就位（第 0/0.5 遍）。没有骨架就直接进入"微课对话"会重新退化成"读百科"。

## 四、苏格拉底式追问规则

| 用户状态 | LLM 动作 |
|---|---|
| **答对** | 下钻一层：追问"为什么 / 如果……会怎样"（因果型）——不要只说"对" |
| **答半对** | 先肯定对的部分，对偏的部分给**最小提示**，再问一次 |
| **答错** | 退回**地基语言**给最小提示，再问；仍错才给答案，并记入缺口账本 |
| **沉默/不会** | 把问题拆小，先问一个更基础的识别型问题 |

**绝不在用户思考前直接给答案。**

## 五、防跑题与防"假懂"

- **开场声明目标**：本轮聚焦 `<要素 · Q编号>`，写在最前面。
- **岔路处理**：用户偏题 → 记入 park 清单，本轮结束后再处理，先拉回目标。
- **关书复述**：每完成一个要素，让用户**合上笔记**复述连结关系图（顶层要素如何各自作用在地基上）。
- **客观锚**：爽感 ≠ 掌握。以 `01-问题索引.md` 的 `[x]` 与 `02-缺口账本.md` 为唯一客观标准。

## 六、对话 ↔ Wiki 同步规范

| 对话中发生的事 | 写到哪里 |
|---|---|
| 讲清一个单元 | `wiki/<分类>/<要素>/index.md` 的 Q<n>（模板见 unit-template.md） |
| 判定结果 | `wiki/01-问题索引.md` 状态列 → `[x]` / 退回 `[ ]` |
| 用户答错 | `wiki/02-缺口账本.md` 新增 open 行 |
| 现实追问 | `wiki/应用/钉子表.md` |
| 每轮结束 | `log.md` 追加 `## [YYYY-MM-DD] 对话 | <要素>·Q<n>` |
| 公式 / 函数图 | math-skill 渲染到该知识点 `wiki/<分类>/<要素>/img/`，正文 `./img/<名>.png` |

## 七、开场与收尾模板

**开场**
1. 定位目标库（本地 / 阿里云盘挂载盘 / 乐享），确认骨架页存在；不存在则转「立骨架对话」。
2. 复述全局：核心问题 ＋ 领域公式 ＋ 地基元素（一两句）。
3. 让用户选：按 `01-问题索引.md` 顺序，还是从某要素切入。

**收尾（每个单元 / 每次会话结束）**
1. 更新 `log.md`。
2. 给出**下一轮建议**（下一个 Q 编号）。
3. 完成一个要素时，鼓励**重绘连结关系图**，存入该页 `img/`（可选）。

## 八、反模式

| 反模式 | 表现 | 修正 |
|---|---|---|
| 单向讲课 | 一路讲，用户只"嗯" | 每轮必须有提问 |
| 一次灌多个单元 | 一轮里讲了 5 个知识点 | 一单元一循环 |
| 只聊不落库 | 聊得很爽，Wiki 没变化 | 每轮执行「沉淀」拍 |
| 错就立刻给答案 | 用户失去思考 | 先最小提示，再问 |
| 对话当真相源 | 结论只在聊天里，Wiki 过期 | Wiki 为准，聊完回写 |
| 跳过骨架 | 直接问"教我微积分" | 先做立骨架对话 |
