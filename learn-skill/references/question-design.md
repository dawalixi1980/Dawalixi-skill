# 问题与钉子设计指南（D v4）

> 问题质量决定学习效果。本文件指导设计高质量问题（供一体单元用）与"穿针钉子"（现实问题）。

## 一、问题设计原则

1. **具体直观，拒绝空泛**
   - ❌ "什么是路基？"（可背定义但无锚点）
   - ✅ "路堤和路堑怎么区分？填高挖深怎么判断？"
2. **指向"机制"与"协同"**——D v4 的核心是机制：
   - ❌ "导数的定义？"（名词解释）
   - ✅ "导数是怎么作用在函数上、把'变化'变成'数'的？"
3. **一个问题对应一个一体单元**：问题要能由该单元的「符号」直接回答。
4. **成链、由浅入深**：要素识别（是什么）→ 协同关系（怎么联动）→ 细节参数（具体数值）。
5. **可自测**：必须能在不看答案时尝试回答；避免开放到无法判对错。

## 二、问题类型图谱（含 D v4 新增的"机制型"）

| 类型 | 引导词 | 学习目的 | 挂载 |
|---|---|---|---|
| 识别型 | 什么是 / 怎么区分 / 属于哪类 | 建立要素节点 | 顶层要素 |
| **机制型**（★核心） | 它是怎么作用在……上的 / 为什么依赖……才成立 | 打通"地基 → 要素" | 地基支撑线 |
| 因果型 | 为什么 / 如果不…会怎样 | 理解协同关系 | 要素间协同线 |
| 流程型 | 先做什么后做什么 | 掌握协同路径 | 协同链 |
| 定量型 | 数值是多少 / 什么标准 | 挂载叶子参数 | 细节 |
| 判断型 | 什么时候用 A 而非 B | 区分易混概念 | 要素对比 |

## 三、问题分层（与骨架结构对应）

1. **第 1 层（1–5 题）**：顶层核心问题 + 地基元素识别 → 建立全局观（答案在 `00-骨架.md`）。
2. **第 2 层（6–15 题）**：各要素的机制与协同 → 沿地基爬升（答案在要素页）。
3. **第 3 层（16+ 题）**：叶子参数与细节 → 挂载数值/规则。

## 四、穿针钉子（现实问题）设计

钉子是"答案有意义"的现实问题，用于证明知识"能用"。字段：

| 现实问题 | 顶坐标（要素） | 底坐标（地基） | 为何答案有意义 |
|---|---|---|---|
| 速度表如何从里程算出？ | d/dx | 函数 | 把"变化率"变成可读的数 |
| 不规则湖面面积怎么算？ | ∫ | 函数 | 把"累积"变成可测量的面积 |
| 神经网络如何更新权重？ | d/dx → FT | 函数 | 梯度下降依赖对损失函数求导 |

**设计要点**
- ❌ 课后纯计算题（只考背/算，不连现实）。
- ✅ 答案能改变你对现实的判断或动作。
- 每个主要要素至少 2–3 个钉子；顶坐标 + 底坐标都要标。

## 五、每份资料摄入时应产出

- ≥3 个**识别型**问题（确立新要素/节点）
- ≥2 个**机制型**问题（打通地基 → 要素）★
- ≥1 个**因果/流程型**问题（强化协同）
- ≥1 个**定量型**问题（挂载关键参数）
- ≥1 个**钉子**（现实问题）

## 六、自测清单（写完核对）

- [ ] 每个问题都能用"是/否"或"一个值/一句话"判断对错
- [ ] 存在**机制型**问题（"它如何作用在地基上"）
- [ ] 问题按从根到叶排序，有递进关系
- [ ] 每个问题答案中都含「定位」（挂载点）
- [ ] 没有两个问题答案相同（避免重复挂载）
- [ ] 钉子表里没有纯计算题
