# learn-skill — 顶层整体 ＋ 贯穿地基的深度学习

学习不是"读百科"，而是：**先立顶层整体 → 找到贯穿它的地基元素 → 用地基"钉穿"顶层每个角落 → 再用现实问题穿针验证**。

> 本 skill 的完整理论在 [references/learning-arch-d.md](references/learning-arch-d.md)。教学前必读。

## 相关 skill 分工（不要重复造）

| Skill | 职责 |
|---|---|
| **learn-skill（本件）** | 教学与结构层：顶层架构、地基元素、一体知识点单元、学习路径 |
| `llm-wiki-skill` | 持久化底座：目录/链接规则、资料源双模式（本地 / IMA） |
| `math-render`（仓库名 `math-skill`） | 渲染层：公式 → PNG、函数/几何图 → PNG、Mermaid 转图 |

## 核心模型：一页骨架，两个尺度

```
骨架（顶层整体）   核心问题 + 领域公式 领域 ≝ ⟨要素…⟩ + 协同图
        ▲ 连结关系图（支撑线：作用于 / 相对它成立 / 由它组成）
地基（贯穿元素）   一个（或极少数）基本原子 ── 顶层一切共同作用的对象 / 前提
```

**关键铁律**：顶层与地基**不是两张图**，而是同一件事的不同尺度。Wiki 里只维护**一张**「连结关系图」，地基在下、顶层在上。

- 判定地基元素：**删掉它，顶层每个要素都失去意义**；顶层每件事都作用在 / 相对它发生。
- 三形态：**对象型**（如微积分→函数）/ **背景型**（如牛顿力学→惯性系）/ **原料型**（如 Python→对象）。
- 必须通过「贯穿度自检表」：逐要素打勾，全部命中才算地基。详见 learning-arch-d.md 第三节。

## Wiki 持久化结构

初始化：`python <skill-dir>/scripts/init-wiki.py --path <项目目录> --domain "<领域名>"`

```
<项目>/
├── raw/源文件清单.md
├── raw/images/                 # 输入原图（截图/拍照/书本图）— 只读存档
├── media/<slug>.md             # 图片的图文卡（OCR/描述/洞察）— 让图片可检索
├── index.md  log.md  WIKI-SCHEMA.md
└── wiki/
    ├── 00-骨架/                ★ 知识点＝文件夹：index.md + img/
    │   ├── index.md            # 顶层三件套 + 地基元素 + 连结关系图（双向标注）
    │   └── img/
    ├── 01-问题索引.md           # 从根到叶的问题表 + 1/3/7/30 掌握状态
    ├── 02-缺口账本.md           # 第 2 遍自测答不出的真缺口（open / resolved）
    ├── 索引-<分类>.md
    ├── <分类>/<要素>/           # 每个顶层要素 = 一个文件夹
    │   ├── index.md            # 要素页 = 若干「一体知识点单元」
    │   └── img/                # 该知识点的公式图/函数图
    └── 应用/钉子表.md            # 现实问题穿针（现实问题 / 顶坐标 / 底坐标）
```

**一个知识点 = 一个文件夹**，图片跟知识点走。页面模板与链接规则见 [references/wiki-layout.md](references/wiki-layout.md)。

## 一体知识点单元（两档）

- **最小档（默认）**：`问题 → 符号 → 语义 → 机制(作用在地基元素上) → 定位`
- **完整档（复杂概念）**：再加 `协同演示`、`双向标注`、`应用钉子`

模板与示例见 [references/unit-template.md](references/unit-template.md)。**机制**是本架构的命根子——每个单元都必须说清"它如何作用在地基元素上"。

## 学习路径（5 阶段 → 工作流）

| D v4 阶段 | 动作 | 产出 |
|---|---|---|
| 第 0 遍 · 整体 | 立核心问题 + 领域公式 + 协同图 | `00-骨架/index.md`（三件套） |
| 第 0.5 遍 · 找地基 | 锁地基元素 + 贯穿度自检 | 骨架页补「地基元素」节 |
| 第 1 遍 · 爬升 | 逐要素教学（每要素 = 1 文件夹 + ≥1 单元） | `<分类>/<要素>/index.md` |
| 第 2 遍 · 下山自测 | 只看公式，自推每要素如何作用在地基上 | `02-缺口账本.md` |
| 应用穿针 | 每要素 2–3 个现实问题 | `应用/钉子表.md` |

复习：`01-问题索引.md` 按 **1 / 3 / 7 / 30 天** 复查，只看问题不看答案。
完整流程（建库 / 摄入 / 教学 / 自测 / 复习 / 健康检查 / IMA 模式）见 [references/workflows.md](references/workflows.md)。

## 公式与图：跟随知识点渲染成 PNG

公式/函数图**默认渲染成图片**再嵌入（终端不渲染 LaTeX）。规则：**生成图属于哪个知识点，就放那个知识点的 `img/` 里**：

```bash
node <math-skill>/scripts/render_formula.js "<latex>" -o <项目>/wiki/<分类>/<要素>/img/<名>.png
python <math-skill>/scripts/render_plot.py spec.json -o <项目>/wiki/<分类>/<要素>/img/<名>.png
```

正文用相对路径嵌入 `![图注](./img/<名>.png)`；frontmatter `images:` 登记本页图片，`symbol` 存 LaTeX 源码；Mermaid 同时保留代码块。详见 [references/workflows.md](references/workflows.md) 的「渲染规范」。

## 图片资料归档（截图 / 拍照 / 书本图）

图片是与 Markdown 平等的一等资料。**图片本身不可 grep**，所以每张输入图都要配一张"文字层"图文卡：

| 类型 | 存放 | 说明 |
|---|---|---|
| **输入原图** | `raw/images/YYYYMMDD-<slug>.<ext>` | 只读不可变 |
| **图文卡** | `media/<slug>.md` | OCR + 公式LaTeX + 视觉描述 + 关键洞察 → **可检索** |
| **生成图** | `wiki/<分类>/<要素>/img/` | 跟知识点走（公式/函数图） |

**多模态摄入**：收图 → 多模态读图（OCR/公式/描述/洞察四件套）→ 写图文卡 → 归属到要素并引用 → 公式用 math-skill 复现。

完整规范（图文卡模板 / 命名 / 引用 / 检查清单）见 [references/media.md](references/media.md)。

## 母知识来源（三种 ＋ 图片）

**母知识 = Wiki 的事实依据（source knowledge）。** 它可以来自三种源，全部登记到 `raw/源文件清单.md`；Wiki 只是对母知识的编译成果，母知识始终是单一事实源。

| 母知识来源 | 形态 | 摄入方式 | 原文件去向 |
|---|---|---|---|
| **上传** | 对话中拖入/粘贴的文件（PDF、Office、md、URL 等） | 先归档再读取 | 存入 `raw/` |
| **本地** | 项目/工作区内文件、Obsidian 仓库、已有笔记 | 直接读取 | 存入或登记 `raw/` |
| **IMA 知识库** | 个人/共享向量库 | `ima-skill` 的 `search_knowledge` 向量检索识别 | **不下载**，仅在 `raw/源文件清单.md` 登记 |
| 图片（任意来源） | 截图 / 拍照 / 书本图 | 多模态读图 → 图文卡 | 原图 `raw/images/` + `media/<slug>.md` |

**统一原则**：不论哪个来源，进入 Wiki 前都要么**归档到 `raw/`**（上传/本地），要么**登记到 `raw/源文件清单.md`**（IMA）。这样母知识可追溯、可回查，且 `raw/` 对 LLM 只读。

> 来源判断口诀：**"这段知识从哪来的？"** → 上传的 / 本地已有的 / IMA 库里的 / 一张图。
