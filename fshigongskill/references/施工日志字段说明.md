# 施工日志 docx 字段说明

由 `scripts/generate_log_docx.py` 依据 `日志数据.json` 生成。字段含义与填写规范如下。

## 一、基本信息

| JSON 字段 | 说明 | 必填 |
|-----------|------|:---:|
| 工程名称 | 工程全称；缺省时取 `--project` | 是 |
| 施工单位 | 承接施工的企业名称 | 是 |
| 日期 | 由 `--date` 参数传入，勿写在 JSON 内 | 是 |
| 天气 | 如 `晴 25-32℃`、`小雨` | 是 |
| 记录人 | 当日日志记录人 | 是 |

## 二、施工记录表（施工日志[]）

每一条记录对应一次工序作业，必须齐全以下定位要素，这是审计追溯的基础：

| JSON 字段 | 说明 | 必填 |
|-----------|------|:---:|
| 时间 | 作业时间段，如 `09:00-11:00` | 是 |
| 标段 | 如 `A标段` | 是 |
| 桩号/部位 | 如 `1号桩`、`K1+200`、`主楼3层` | 是 |
| 工序 | 用标准词，见 `references/工序词表.md` | 是 |
| 施工内容 | 做了什么、完成情况（数量/长度/方量等） | 是 |
| 班组/机械/材料 | 参与班组、主要机械、进场材料 | 建议 |
| 验收情况 | 隐蔽工程验收结论（谁验、是否合格）、自检结果 | 隐蔽工序必填 |
| 照片 | 本记录对应的归档照片文件名列表（数组） | 建议 |

## 三、附记

| JSON 字段 | 说明 |
|-----------|------|
| 质量安全及问题处理 | 当日质量问题、安全隐患及处理措施 |
| 设计变更与技术交底 | 当日收到/发出的变更通知、交底内容 |
| 各方协调沟通 | 与村委、业主、监理、设计等沟通事项（对应 `前期协调/`） |
| 次日施工计划 | 次日计划作业的标段/桩号/工序 |

## 四、签认

docx 末尾自动生成：
- 记录人签字
- 项目技术负责人签字

## 填写红线

1. **禁止编造**：施工内容、照片、验收结论必须真实可查；照片以 `照片归档/` 内实际存在的文件为准。
2. **要素完整**：缺标段/桩号/工序/日期时，向用户追问补齐，不猜测。
3. **隐蔽对应**：凡工序含「隐蔽」，日志「验收情况」必须写明验收人和结论，照片自动复制到 `隐蔽工程/`。
