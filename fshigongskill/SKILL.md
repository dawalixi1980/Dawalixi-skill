# 施工日志（PaddleOCR 版）Skill

工作流来自 Obsidian 画板 `shigong skill.canvas`：

```
用户发送图片（今日水印风格）→ PaddleOCR 识别 → 生成施工日志（逐日 Word，排版美观）
```

核心思想：**现场拍照带"今日水印"，识别即归档，逐日自动产出排版美观的施工日志 Word**，零人工誊抄。

## 一、工作流程

### 1. 收集照片
用户发送当日带水印的施工照片（可多张）。先尽量从照片水印/识别文本中提取定位要素：
- **日期**（水印中通常已含）
- **标段/路段**（如 `A标段`、`璟湾路`）
- **桩号/部位**（如 `1号桩`、`K1+200`、`主楼3层`）
- **工序**（如 `浇筑`、`钢筋绑扎`、`隐蔽工程`）

### 2. PaddleOCR 识别照片文字
对每张照片调用识别脚本（依赖 `requests`，已内置 API token）：

```bash
python scripts/paddleocr_to_text.py <图片路径或URL> [更多图片...] --out-dir output
```

- 支持本地路径或 http(s) URL，可一次传多张。
- 识别结果保存为 `output/doc_N.md`，stdout 打印识别文本，供 AI 解析施工要素。
- 若水印文字即"日期+标段+桩号+工序"，直接以此为日志依据。

### 3. 单次提问（最多一轮，铁律）
OCR 完成后，汇总**仍缺失的定位要素**（日期/标段/桩号/工序）。**只允许提问一轮**，用 question 工具把缺失项一次性列全，并提供推荐默认值。用户回复后**立即进入下一步，无论是否补齐，绝不二次追问**。

### 4. 自动兜底（未补齐项用默认值，禁止再问）
用户答复后，仍未明确的字段按以下默认值兜底，直接进入生成流程：

| 字段 | 兜底规则 |
|------|---------|
| 日期 | 取水印/识别文本中的日期；识别不到则用当天日期 |
| 工程名称 | 取水印中的工程名；没有则用 `--project` |
| 标段/路段 | 取水印路段名；没有则填 `A标段` |
| 桩号/部位 | 取水印桩号；没有则填 `全场` |
| 工序 | 从识别文本中提取（浇筑/检验/绑扎等）；提取不到则填 `施工` |
| 天气 | 取水印天气；没有则填 `—` |
| 记录人/班组/机械/材料/验收情况 | 一律留空，不臆测 |

生成 Word 后，在回复中**一次性列出哪些字段使用了兜底默认值**，方便用户核对，但不再阻塞等待。

### 5. 整理日志数据
把识别出的施工内容整理为 `日志数据.json`（结构见 `references/施工日志字段说明.md`）：

```json
{
  "工程名称": "XX工程",
  "施工单位": "XX公司",
  "天气": "晴 25-32℃",
  "记录人": "张三",
  "施工日志": [
    {
      "时间": "09:00-11:00",
      "标段": "A标段",
      "桩号/部位": "1号桩",
      "工序": "浇筑",
      "施工内容": "...",
      "班组/机械/材料": "...",
      "验收情况": "...",
      "照片": ["2026-07-14_A标段_1号桩_浇筑.jpg"]
    }
  ],
  "质量安全及问题处理": "...",
  "设计变更与技术交底": "...",
  "各方协调沟通": "...",
  "次日施工计划": "..."
}
```

> AI 校正：OCR 可能有同音/形近错字（装→桩、胶柱→浇筑、图方→土方），生成 Word 前用规范要素校正施工内容，原始识别文本保留备注。

### 6. 初始化项目目录 + 归档照片（自动）
先建项目骨架，再按命名规范归档照片（**自动执行，不提问**）：

```bash
python scripts/init_project.py "项目名称" --base-dir 输出根目录
python scripts/archive_photos.py --project "项目名称" --manifest 照片清单.json --base-dir 输出根目录
```

照片清单.json（数组，每项一张）：
```json
[
  {"source": "D:/手机导出/IMG_001.jpg", "日期": "2026-07-23", "标段": "璟湾路", "桩号/部位": "K0+000", "工序": "浇筑"}
]
```

归档规则（脚本自动处理）：
- 目标名 = `<日期>_<标段>_<桩号/部位>_<工序>[_<序号>].jpg`
- 归档到 `<项目根>/照片归档/按标段/<标段>/<日期>/<工序>/`
- 工序含「隐蔽」自动复制一份到 `<项目根>/隐蔽工程/`

### 7. 生成排版美观的 Word（逐日）
```bash
python scripts/generate_log_docx.py --project "项目名称" --date YYYY-MM-DD --data 日志数据.json [--base-dir 输出根目录]
```

排版规范源自 **word-formatter skill 的 `simple_modern`（现代简约）模板**，`generate_log_docx.py` 已内置实现，勿随意改动：

| 元素 | 样式 |
|------|------|
| 页面 | A4 横向，页边距 20mm，页脚居中页码"第 N 页" |
| 标题 | 深蓝 #1976D2 加粗居中 20pt + 底部强调线 |
| 信息表 | 标签列浅蓝 #E8F0FE 底加粗，值列常规 |
| 施工记录表 | 表头深蓝 #1976D2 底白字加粗，奇数行浅灰 #F2F2F2 斑马纹，浅灰 #BFBFBF 细边框，单元格垂直居中 + 内边距适中 |
| 附记 | 分节小标题深蓝加粗 |
| 照片附图 | 两列表格网格排版，照片居中带浅灰边框，图注 9pt 灰色居中 |
| 字体 | 中文宋体，数字/西文 Times New Roman |

- 产物：`<项目根>/施工日志/YYYY-MM-DD_施工日志.docx`，含当日照片。
- **每日一份**：当天内容当天生成，日期从文件名区分，不覆盖历史日志。
- **文件被占用时**：若目标 docx 正在 Word 中打开导致 PermissionError，改用 `_v2` 后缀输出并提示用户先关闭旧文件。

### 8. 验证
打开 docx 确认：表格完整、标段/桩号/工序对应无误、照片正确插入。

## 二、照片命名规范（强制）

```
<日期>_<标段>_<桩号/部位>_<工序>.jpg
```

示例：`2026-07-14_A标段_1号桩_浇筑.jpg`；同日同桩号同工序多张追加 `_1`、`_2`。由 `archive_photos.py` 依据照片清单自动重命名归档。

## 三、质量红线

- **只问一轮**：定位要素缺失时最多提问一次，用户答复后立即进入生成流程，绝不二次追问。
- **禁止编造**：施工内容、照片、验收结论必须真实，以照片水印/识别文本为据；兜底字段在结果中标注"使用默认值/留空"。
- **自动兜底**：未补齐要素按默认值处理（见"自动兜底"表），不阻塞生成。
- **当日事当日毕**：照片当天识别、当天生成 Word。
- **隐蔽工程留底**：工序含「隐蔽」（钢筋绑扎、地基验槽、防水施工等），日志"验收情况"必须写明验收人与结论，照片自动复制到 `隐蔽工程/`。

## 四、依赖

- `pip install requests`（PaddleOCR 调用）
- `pip install python-docx`（Word 生成）

> 排版规范吸收自 **word-formatter skill**（`simple_modern` 现代简约模板），已直接编码进 `scripts/generate_log_docx.py`，运行时无需再调用 word-formatter。

## 五、常见问答

- **照片是水印文字版**：直接用 `paddleocr_to_text.py` 识别水印文字，作为定位要素依据。
- **照片没水印/识别不出**：要素缺失时一次问齐（标段/桩号/工序/日期），用户答复后按兜底默认值生成，不再追问。
- **每天多张照片**：逐张识别、合并到当天 `日志数据.json`，Word 中"对应照片"列逐张列出并附图。
- **历史补记**：可指定任意 `--date` 回补，不覆盖当天已生成的 docx。
