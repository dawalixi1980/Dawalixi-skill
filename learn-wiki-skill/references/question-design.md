# 问题设计指南

> 本文件指导如何设计高质量问题——learn-wiki-skill 的核心燃料。问题质量决定学习效果。

## 问题设计原则

### 1. 具体直观，拒绝空泛
- ❌ "什么是路基？"（可背诵定义，但无记忆锚点）
- ✅ "路堤和路堑怎么区分？填高挖深怎么判断？"

### 2. 指向"为什么"与"怎么协同"
- ❌ "压实度的定义？"（名词解释）
- ✅ "压实度不足会传给下游什么后果？"（触发协同链：路基 → 路面）

### 3. 一个三元组对应一个核心问题
每个「问题 → 符号 → 知识点」单元只解决一个困惑，问题要能由该符号直接回答。

### 4. 问题之间成链，由浅入深
问题按"从根到叶"排序：先要素识别（是什么）→ 再协同关系（怎么联动）→ 后细节参数（具体数值/规则）。

### 5. 可自测性
问题必须能在**不看答案**的情况下尝试回答——这是间隔复习的前提。避免开放到无法判对错。

## 问题类型图谱

| 类型 | 引导词 | 学习目的 |
|------|--------|----------|
| 识别型 | 什么是 / 怎么区分 / 属于哪类 | 要素识别，建立节点 |
| 因果型 | 为什么 / 如果不…会怎样 | 理解协同关系 |
| 定量型 | 数值是多少 / 什么标准 | 挂载叶子参数 |
| 流程型 | 先做什么后做什么 | 掌握协同路径 |
| 判断型 | 什么时候用 A 而非 B | 区分易混概念 |

## 三元组示例（道路工程）

```
Q：路基为什么必须压实？
符号：压实度 K = ρd / ρdmax（重型击实标准）
知识点：
  解释：压实排除孔隙水气，提高强度与稳定性
  定位：挂载在"路基 → 路面"协同线
  协同演示：路基压实不足 → 路床顶面回弹模量低 → 传给路面设计弯沉 → 路面早期破坏
```

## 问题索引的分层

1. **第 1 层**（1-5 题）：顶层核心问题与要素识别——建立全局协同观。
2. **第 2 层**（6-15 题）：主干要素的核心原理——沿协同路径深入。
3. **第 3 层**（16+ 题）：叶子参数与细节——挂载具体数值/规则。

## 每份资料摄入时应产出

- 至少 3 个"识别型"问题（确立新节点）
- 至少 2 个"因果/流程型"问题（强化协同）
- 至少 1 个"定量型"问题（挂载关键参数）
- 每个问题必须能定位到领域公式的**具体节点或协同线**

## 自测清单（写完问题后核对）

- [ ] 每个问题都能用"是/否"或"一个值/一句话"判断对错
- [ ] 问题按从根到叶排序，存在递进关系
- [ ] 每个问题答案中都有「定位 + 协同演示」
- [ ] 没有两个问题答案相同（避免重复挂载）
