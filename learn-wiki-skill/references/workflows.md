# 工作流 — 摄入 / 查询 / 复习 / 健康检查

> 本文件是 learn-wiki-skill 的操作层。每次摄入资料、每次查询、每次复习都按本文件执行。

## A. 建立新的学习 Wiki

```bash
python <skill-dir>/scripts/init-wiki.py --path <项目目录> --domain "<领域名>"
```

脚本生成骨架后，**必须完成**：
1. 确定**顶层核心问题**，写入 `wiki/00-领域公式.md`。
2. 提炼**领域公式** + 输出 **Mermaid 分层协同架构图**。
3. 创建 `wiki/01-问题索引.md` 初版问题清单（≥5 题，由浅入深）。

## B. 摄入资料（核心闭环）

每摄入一份资料，执行以下步骤，**一次只摄入一份以保证质量**：

1. **判断资料源**
   - 本地文件 → 存入 `raw/`（只读存档）。
   - IMA 向量库 → 用 ima-skill 的 `search_knowledge` 向量检索识别内容，仅在 `raw/源文件清单.md` 登记，不下载源文件。
2. **定位挂载点**：这份资料回答哪些问题？对应领域公式的哪个节点/协同线？
3. **提炼三元组**：从资料提取「问题 → 符号 → 知识点（定位 + 协同演示）」，写入对应节点页。一份资料可触及 10-15 个三元组。
4. **更新问题索引**：新增问题按"从根到叶"排入 `01-问题索引.md`，填答案位置与状态。
5. **必要时修订根**：资料揭示要素间新协同时，更新 `00-领域公式.md` 的公式与架构图。
6. **记录日志**：`log.md` 追加一条。
7. **健康检查**：断链 / 单向链接 / 孤立页。

## C. 查询（向 Wiki 提问）

1. 从 `01-问题索引.md` 或 `index.md` 找到相关问题。
2. **先自答**（检索练习，激活记忆）。
3. 对照节点页答案纠偏。
4. 答错的点沿「协同演示」回溯到领域公式根，理解其协同位置。
5. 有价值的问答**归档为新的三元组**写入 Wiki，不流失在对话中。

## D. 间隔复习（保持知识活性）

1. 按 **1天 / 3天 / 7天 / 30天** 间隔复查问题索引。
2. 复习时**只看问题不看答案**。
3. 答对标记 `[x]`（记日期）；答错降级回 `[ ]` 并补强该三元组的协同演示。

## E. 健康检查（定期）

- 搜索 `](./xxx.md)` 模式，验证每个目标文件存在（无断链）。
- 对页面 A 上每个链接，验证页面 B 有返回 A 的链接（无单向链接）。
- 检查孤立页面（无入链）。
- 检查被新资料取代的过时观点。
- 可用 grep 解析 `log.md` 追踪摄入历史。

## 教学触发

当用户要求"学习/教我"某领域时，LLM 直接按 [learning-architecture.md](learning-architecture.md) 的 7 条教学要求授课，并把授课过程逐步持久化为 Wiki 页面（同步执行本文件的 B/C 流程）。

## 资料源模式细节

### IMA 向量库模式
1. 先加载 ima-skill，校验凭证。
2. 用 `search_knowledge_base`（query 传空）盘点知识库，定位目标库。
3. 用 `search_knowledge` 做多主题语义检索，读取 `title`/`highlight_content` 判断资料重点。
4. 用 `get_knowledge_list` 按文件夹浏览确保无遗漏。
5. 仅在 `raw/源文件清单.md` 登记，绝不下源文件。
6. 需要原文时用 `get_media_info` 获取 URL 按需读取。
