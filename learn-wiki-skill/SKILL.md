# Learn Wiki Skill — 问题驱动的学习 Wiki

## 核心理念

学习不是"读百科"，而是**检索练习**：先被问题卡住，再去找答案，记忆才牢固。

本技能将两个成熟模式融合：
- **学习架构 A**：以「顶层核心问题 → 领域公式（协同架构图）→ 三元组学习单元 → 从根到叶」组织教学，确保知识不孤立、可协同运行。
- **llm-wiki**：将教学过程增量持久化为 Markdown Wiki，每次学习都在复利增长。

**一句话**：Wiki 平铺直述是"查阅"，本技能让 Wiki 成为"习得"——每一页都从一个问题出发。

## 与 llm-wiki 的关系

- **继承**：目录结构（raw/ + wiki/ + 元文件）、链接规则、导航栏、双向链接、资料源双模式（本地文件 / IMA 向量库）、健康检查。详见 `llm-wiki-skill/SKILL.md`。
- **核心差异**：本技能的 **wiki/ 内容页不按"知识点罗列"组织，而按"问题→答案→回溯"组织**；并新增一个全局根页面「领域公式」承载协同架构图。

## 目录结构

```
<项目>/
├── raw/源文件清单.md       # 资料登记（同 llm-wiki：本地存档 / IMA 仅登记）
├── index.md                # 学习总入口：顶层核心问题 + 领域公式 + 问题索引导航
├── log.md                  # 操作日志
├── WIKI-SCHEMA.md          # 模式配置
└── wiki/
    ├── 00-领域公式.md       # 【根】顶层核心问题 + 领域公式 + Mermaid 协同架构图
    ├── 01-问题索引.md       # 从根到叶的问题清单（学习入口/自测清单）
    ├── 索引-<分类>.md       # 分类索引页
    └── <分类>/
        ├── <节点>.md        # 每个协同节点一页，内含若干三元组
        └── ...
```

## 三层模型（必须遵守）

### 第 1 层：根 — 领域公式页（`00-领域公式.md`）
每个领域只维护**一个根**：
- **顶层核心问题**：整个领域要回答的根本大问题。
- **领域公式**：`领域 ≝ ⟨要素1, 要素2, …⟩`，用 `→ / ⇄ / ↔` 标注协同关系。
- **Mermaid 分层协同架构图**：必须用 subgraph 分层展示要素层级，用箭头标注数据流/控制流。

> 原则：所有知识点都挂载到这唯一一棵树上，**禁止引入平行核心**。

### 第 2 层：三元组学习单元（每个知识点的基本形态）
每个知识点必须按「问题 → 符号 → 知识点」组织：

```
问题     一个具体直观的疑惑（为什么？是什么？怎么描述？）
符号     对该问题的精确表达（公式/符号/参数/规则）
知识点
  ├ 解释  符号的含义，为什么能回答这个问题
  ├ 定位  挂载在领域公式的哪个节点/哪条协同线上
  └ 协同演示  用符号链 A → B → C 演示如何与架构其他要素联动
```

### 第 3 层：问题索引（`01-问题索引.md`，学习入口）
按"从根到叶"顺序列出核心问题，每条带：
- 问题编号（由浅入深）
- 答案链接（指向对应节点页的锚点）
- 掌握状态（`[ ]` 待掌握 / `[x]` 已掌握）

## 教学要求（LLM 授课时强制）

1. **公式先行，图示并列**：始终从顶层核心问题出发，立刻给出领域公式，**必须**输出 Mermaid 分层协同架构图。
2. **三元组教学**：每个新概念以「问题 → 符号 → 知识点」输出，知识点含"定位"和"协同演示"。
3. **协同链回顾**：每学完一个单元，用完整符号链回顾其在整个核心公式中的协同路径。
4. **单一理论核心**：只维护一个根公式，所有案例/工具/扩展都作为叶子挂载，禁止引入平行核心。
5. **符号化优先**：关系/流程/结构优先用公式、箭头图、表格表达，文字为辅。
6. **从根到叶**：先整体协同，再主干深入，最后叶子挂载；不建立全局图景前不跳入细节。
7. **鼓励协同知识图**：每次教学结束，鼓励学习者重画协同知识图并重新标注核心公式。

## 学习闭环（每次摄入一份资料）

1. **判断资料源**：本地文件 → 存入 raw/；IMA 向量库 → 用 ima-skill `search_knowledge` 识别内容，仅登记 `raw/源文件清单.md`。
2. **定位挂载点**：这份资料回答哪些问题？对应领域公式的哪个节点/协同线？
3. **提炼三元组**：从资料中提取「问题 → 符号 → 知识点」，写入对应节点页。
4. **更新问题索引**：新增问题按由浅入深排入 `01-问题索引.md`。
5. **更新根**：如资料揭示了要素间新协同，修订领域公式页。
6. **日志**：log.md 追加记录。
7. **健康检查**：断链、单向链接、孤立页。

## 查询（向 Wiki 提问）

1. 从 `01-问题索引.md` 或 `index.md` 找到相关问题。
2. 尝试自答（检索练习），再对照节点页答案。
3. 答错的点沿「协同演示」回溯到领域公式根，理解其协同位置。
4. 有价值的问答可归档为新的三元组写入 Wiki。

## 间隔复习（保持知识活性）

- 问题索引中标注掌握日期，按 1天/3天/7天/30天 间隔复查。
- 复习时只看问题，不看答案；答对标记 `[x]`，答错降级回 `[ ]` 并补强协同演示。

## 重要原则

1. **原始资料不可变** — 绝不修改源文档。
2. **LLM 拥有 Wiki** — 用户阅读与提问，LLM 编写与维护。
3. **知识复利增长** — 每次摄入、每次问答都在丰富 Wiki。
4. **归档好答案** — 有价值的分析不得流失在对话历史中。
5. **定期检查** — 维护断链、双向链接、架构一致性。
